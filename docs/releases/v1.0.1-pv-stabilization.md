## 业务侧新能力

### 1. 上网电价 / 碳排因子的管理 UI（[#20](https://github.com/tranhoanganh9373-sudo/factory-ems/issues/20)）

**之前**：电价、碳排因子只能通过 Flyway 迁移配置，运营改价需要研发跑 SQL。

**现在**：`系统管理 → 上网电价 / 碳排因子` 页面，ADMIN 可直接维护：

**设计**：append-only — 历史行只读、置灰，改价 = 新增一行带新生效日。审计安全 + 后端零改动（`findEffective(asOf)` 已支持）。

## Bug 修复

### 2. ResponseStatusException 不再被吞成 500（[#19](https://github.com/tranhoanganh9373-sudo/factory-ems/issues/19)）

Controller 抛 `ResponseStatusException(NOT_FOUND, "channel not found: 14")` 时，前端原本看到 `500 服务器错误`，现在能看到 `404 channel not found: 14`。

**根因**：`GlobalExceptionHandler` 缺 `@ExceptionHandler(ResponseStatusException.class)`，所有 controller 抛的 404/409 都被 catch-all `Exception.class` 转成 500。

**影响**：用户原本以为后端崩了、刷新一下就好的问题（陈旧缓存）也被报告成 P1。修复后状态码语义正确。

### 3. FeedInRevenue 改用 GRID_TIE+EXPORT（[#26](https://github.com/tranhoanganh9373-sudo/factory-ems/issues/26)）

`/cost/savings` 返回 `feedInRevenue=0` 即使现场有真实的上网售电。

**根因**：`FeedInRevenueServiceImpl` 同时要求 `flowDirection=EXPORT && energySource=SOLAR`，但标准 PV 接线是「光伏主表 SOLAR/IMPORT」+「并网出线表 GRID/EXPORT/GRID_TIE」，两表都不满足组合条件。

**修复**：用 `MeterRole.GRID_TIE && FlowDirection.EXPORT` 识别上网点，`source` 参数仅用于 tariff 价格档查询（不再过滤 meter）。

**验证（30 天 mock 数据）**：feedInRevenue 0 → **4,800 元**。

### 4. cost-allocation runs 改用 billPeriodId 消除时区错配（[#24](https://github.com/tranhoanganh9373-sudo/factory-ems/issues/24)）

UI 上选 "2026-03 整月" 跑成本分摊后关账期，会神秘地返回 `409 No SUCCESS cost_allocation_run covers...`。

**根因**：`BillPeriod` 边界存 Asia/Shanghai (UTC+8)，`cost-allocation/runs` API 接收 UTC ISO，比较时差 8h。前端"自然月"时间戳被解读成晚 8 小时，run 不覆盖 period。

**修复**：API 改用 `{billPeriodId, ruleIds}`，后端从 `bill_period` 直接读边界。**单一真相源，物理上不可能再错配。**

**架构改动**：新增 `BillPeriodLookupPort`（ems-cost）+ `BillPeriodLookupAdapter`（ems-billing），保持模块依赖方向不变。

**前端**：`/cost/runs` 页面提交时先 `ensurePeriod(ym)` 拿到 id，再 submit。

## 测试基础设施

### 5. e2e 套件全部修复（[#16](https://github.com/tranhoanganh9373-sudo/factory-ems/issues/16) + [#22](https://github.com/tranhoanganh9373-sudo/factory-ems/issues/22)）

PR #15 修了 container 启动后 Playwright 跑全套，结果 33/52 失败、用时 30+ 分钟。本次清理：

- **Category A/B/D/E**（PR #18）—— 12 个 spec 的陈旧 selector / 文本 assertion
- **Category C**（PR #21）—— 6 个慢 spec timeout 优化（18 min → ~80s）
- **数据前置链**（PR #23）—— `bill-period-lifecycle` + `cost-export` 的 cost-run 前置 fixture（含初版的 -8h 时区补偿，后被 #24 重构清掉）

**结果**：所有 26 个 spec 现在都能跑过且不超过 60s/spec。

### 6. mock-data-generator 拓扑覆盖修复（[#17](https://github.com/tranhoanganh9373-sudo/factory-ems/issues/17)）

之前 mock 表只生成 `MOCK-` 前缀的 meter 读数，但 `meter_topology` 中可能引用用户手建的非 MOCK 表 → 拓扑里这些表变成"幽灵节点"（看板可见但无读数）。

**修复**：filter 扩展到包含 topology 中所有 meter，新增 `validateTopologyCoverage` 在启动时 fail-fast。

| `POST /api/v1/feed-in-tariff` | 新增 | ADMIN-only |
| `GET  /api/v1/feed-in-tariff` | 新增 | 任意已登录用户 |
| `POST /api/v1/carbon-factor` | 新增 | ADMIN-only |
| `GET  /api/v1/carbon-factor` | 新增 | 任意已登录用户 |
| 全局错误码 | 行为修复 | controller 抛 `ResponseStatusException(404)` 现在返回 404，不再被吞成 500 |
